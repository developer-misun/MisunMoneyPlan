# 사용자-도반(Doban) 의사소통 가이드

이 문서는 사용자가 개발 파트너이자 학습 조력자인 **도반(Doban)**과 협업할 때 효율적으로 업무를 지시하고 상호작용하는 방법을 설명합니다.

## 1. 첫 시작 가이드 (Getting Started)
새로운 환경에서 도반을 처음 만났을 때, 다음 스크립트를 사용하여 프로젝트의 문맥을 빠르게 주입하십시오.

- **권장 첫 메시지**: 
  > "이 프로젝트는 `.ai/` 폴더 내의 문서들을 기반으로 관리되고 있어. 우선 [**AGENT_GUIDE.md**](system/AGENT_GUIDE.md)와 [**RULES.md**](system/RULES.md)를 정독하고, 현재 프로젝트의 아키텍처와 진행 상황을 파악해서 보고해줘. 너는 나의 개발 파트너이자 학습 조력자인 **'도반'**이야. 대화는 항상 이모티콘 없이 담백한 톤을 유지해야 해."

- **파악 여부 확인**: 도반의 보고가 끝나면, `system/AGENT_GUIDE.md`의 '현재 프로젝트 스냅샷' 내용과 일치하는지 확인하여 온보딩 성공 여부를 판단하십시오.

## 2. 기본 의사소통 원칙
- **역할 지정**: 요청 시 특정 에이전트 역할을 언급하면 해당 가이드(`system/agents/`)를 바탕으로 사고합니다.
- **제안 선행 요구**: "구현해" 보다는 "**니 생각을 정리해서 제안해**"라고 먼저 물으십시오.
- **문서 확인 강제**: "규칙에 따라 문서를 먼저 업데이트하고 진행해"라고 지시하여 정의 우선 원칙을 상기시키십시오.

## 3. 분야별 요청 샘플 (Sample Requests)

### [관리자(Manager)] 전체 진행 및 규칙 관리
- **샘플**: "관리자 도반, 현재 프로젝트 로드맵 대비 진행률을 체크해주고, TASK_LOG에 누락된 태스크가 없는지 검토해줘."

### [아키텍트(Architect)] 설계 및 기획 구체화
- **샘플**: "아키텍트 도반, 자산 상세 화면에 '히스토리 보기' 기능을 추가하고 싶어. 화면 명세(SCR-02)를 업데이트하고 HTML 목업으로 레이아웃을 먼저 보여줘."

### [로직(Logic)] 비즈니스 로직 및 테스트
- **샘플**: "로직 도반, 자산 비중 계산 로직에 소수점 둘째 자리 반올림 규칙을 추가해야 해. TEST_LOG에 케이스를 먼저 만들고 단위 테스트부터 진행해줘."

### [UI(UI)] Compose 및 시각화
- **샘플**: "UI 도반, 홈 화면의 트리맵 차트 색상이 너무 어두워. UI_UX_SPEC의 테마에 맞춰서 파스텔 톤으로 조정하고 Preview로 결과를 보여줘."

### [데이터(Data)] DB 및 외부 연동
- **샘플**: "데이터 도반, AssetEntity에 '취득가액' 필드를 추가해야 해. DB 마이그레이션 계획을 세우고 Mapper에 변환 로직을 추가하는 설계를 보여줘."

### [교육(Trainer)] 기술 설명 및 학습
- **샘플**: "교육 도반, 우리 프로젝트에서 사용 중인 Hilt 주입 방식에 대해 설명해줘. 실제 사용 중인 모듈 파일을 예시로 들어서 study/ 폴더에 정리해줘."

## 4. 대화의 선순환 (Feedback Loop)
1. **사용자**: (아이디어 제안 또는 문제 제기)
2. **도반**: (분석 결과 및 작업 계획 제안 - Step 1~N)
3. **사용자**: (계획 승인 또는 수정 요청)
4. **도반**: (문서 선 업데이트 후 단계별 실행 및 보고)

## 5. 팁: 도반이 규칙을 잊었을 때
도반이 문서화 없이 바로 코드를 수정하려고 한다면 다음과 같이 말씀하십시오.
> "이봐, **정의 우선 원칙**을 잊었어? AGENTS.md랑 계획부터 다시 가져와."
